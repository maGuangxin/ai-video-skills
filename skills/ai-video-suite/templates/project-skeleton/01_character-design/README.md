> 存放所有角色完整设定 + 一致性约束 + 角色展示图 / 角色参考图。
> 一致性约束文档中的 3.1/3.2/3.3 三行完整前缀是 SK4 提示词「完整前缀强制复制法」的真相源，要改必须统一改这里，不允许在单段提示词里私自改写。

## 两个子目录：
| 子目录 | 内容 | 谁生成 |
|---|---|---|
| `docs/` | 每个角色 1 份 `char-<id>-full-design.md` + `character-consistency-rules.md`（含 3.1/3.2/3.3 3 行前缀） | sk1 生成 |
| `references/` | 角色展示图、真实参考图、待验证参考图 | 用户手动放 + provider 验证后生成 |

## references 语义约束

`references/` 下的图片资产必须明确区分为以下三类，不允许混名：

1. `showcase-pack/`
   - 用途：角色展示、风格审阅、沟通确认
   - 禁止默认作为关键帧或视频生成参考输入
2. `reference-pack/`
   - 用途：关键帧、视频生成、多镜头人物一致性约束
   - 前提：真实用户素材充分，且 provider 能力已验证支持
3. `pending-verification/`
   - 用途：尚未证明可稳定约束人物的候选图片
   - 在验证前不得升级为 `reference-pack/`

## 命名语言规则

1. Skill 内部 ID、schema 字段名、API 名保持英文
2. 项目业务目录、业务图片名、业务说明文档名应跟随项目语言环境
3. 若项目语言环境为中文，则优先使用中文或中文语义命名，不应在业务产物中无规则混用英文
