# 依赖关系与跳步规则

本文档描述的是执行契约，不是功能介绍。是否允许启动某一步，以本文件和对应 `SKILL.md` 的前置条件为准。

## 1. 总规则

执行任意 Skill 前，先遵守下面 5 条：

1. 先确认 `sk0_project_init_guided` 已生成 `00_project-config/project-base-config.md`
2. 进入 `sk1` 到 `sk6` 前，先执行 `sk0b_missing_field_guide`
3. 当前步骤需要的关键事实缺失时，暂停，不补写默认值
4. 只有当前步骤的最低输出达成后，才允许继续下一步
5. 进入 `sk3 / sk4 / sk5 / sk6` 前，应先读取模型能力画像和推荐生产路线

## 2. 默认执行顺序

```text
sk0 -> sk0b -> sk1 + sk2 -> sk3 -> sk4 -> sk5
                         └-------> sk6
```

说明：

- `sk1` 和 `sk2` 可以并行
- `sk6` 在 `sk3` 后即可启动
- `sk0b` 是全局 pre-hook，不是一个可省略的装饰步骤

## 3. 强制依赖

| 前一步 | 后一步 | 原因 |
|---|---|---|
| `sk0` | `sk1` / `sk2` | 角色、场景生成依赖项目基础配置与模型能力画像 |
| `sk1` + `sk2` | `sk3` | 分镜拆分需要角色与场景真相源 |
| `sk3` | `sk4` | 提示词依赖分镜时间轴、shot 结构和连续性字段 |
| `sk4` | `sk5` | 审计依赖实际提示词产物 |
| `sk3` | `sk6` | 字幕、TTS 和音频路线依赖时间轴 |

## 4. 可并行节点

| 节点 | 是否可并行 | 说明 |
|---|---|---|
| `sk1` 与 `sk2` | 可以 | 角色与场景设计互不阻塞 |
| `sk4` 与 `sk6` | 可以 | `sk6` 不依赖提示词生成完成 |

## 5. 生产模式与音频路线

`sk0` 应给出推荐模式：

- `safe`：更保守，优先稳定和可剪辑
- `balanced`：兼顾稳定和表现力
- `expressive`：适合较强模型，追求更多镜头变化

同时应给出推荐音频路线：

- `mute_plus_tts`
- `native_audio`
- `hybrid`

后续步骤应按这一配置执行，不应默认所有项目都能走长镜头、原生台词或精细口型。

## 6. 跳步规则

### 入口 1：完整故事

- 默认不跳步
- 适合完整走一遍流程

### 入口 2：故事大纲

- 不跳主流程
- 由 `sk0b` 补齐关键事实后继续

### 入口 3：角色与场景已知

- 可减少前期补采集工作
- 仍建议保留 `sk1`、`sk2`、`sk3`

### 入口 4：单段片段

- 允许只覆盖当前片段相关的角色与场景
- `sk3` 可以只生成单段分镜
- 适合 smoke test

### 入口 5：已有分镜

- `sk0` 后可跳过 `sk1`、`sk2`、`sk3`
- 前提是现有分镜已经能支撑 `sk4` 和 `sk6`

### 入口 6：已有提示词

- `sk0` 后可直接进入 `sk5` + `sk6`
- 前提是现有提示词及相关时间轴信息足够支撑检查和后期生成

## 7. 可继续判定

| 当前步骤 | 允许继续的最低条件 |
|---|---|
| `sk0` | `project-base-config.md` 已生成，关键项已有值或明确标记待确认，且模型能力画像已建立 |
| `sk0b` | 当前目标步骤所需关键项已补齐；未补齐时必须暂停 |
| `sk1` | 角色设定文件和 `character-consistency-rules.md` 已生成 |
| `sk2` | 场景设定文件和 `unified-visual-spec.md` 已生成 |
| `sk3` | 分镜脚本、关键帧约束、连续性字段、shot 目录已生成 |
| `sk4` | 每段 `video-prompt.md` 已生成，且模式与模型能力画像匹配 |
| `sk5` | `project-production-progress.md` 已生成，且已包含连续性和模型适配审计 |
| `sk6` | 字幕、TTS 清单或停用说明、音频路线说明和剪映操作手册已生成 |

## 8. 暂停规则

出现下面任一情况时，当前步骤应暂停：

1. 关键输入文件不存在
2. 关键字段缺失、为空或含义不明确
3. 当前入口虽然允许跳步，但所需替代输入并不存在
4. 需要用户确认事实，且尚未确认
5. 当前模型能力不足，但流程仍试图启用不适合的高强度模式

建议统一输出：

```text
⚠️当前步骤已暂停：缺少继续执行所需的关键信息，或当前模式与模型能力不匹配。
请先确认缺失项或调整生产路线，更新后再继续执行本步骤。
```

## 9. 执行建议

第一次接入时，先跑单段 smoke test，再进入真实项目。

原因很简单：

- 更容易判断 Agent 是否真的遵守暂停规则
- 更容易验证依赖和目录结构是否被正确理解
- 更容易把问题定位到具体步骤
- 更容易先验证当前模型适合哪条生产路线
