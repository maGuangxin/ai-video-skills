## 一、强制串行边表（必须等上一步 100% 完才能跑下一个，不允许并行）

| 强制串行边（前 → 后） | 为什么必须串行，不允许并行？ |
|---|---|
| sk0_project_init_guided → sk1_character_design / sk2_scene_design | sk1/sk2 需要 SK0 12 项初始化配置结果（风格/人数/画幅/一致性难度），没配就不知道要填多少个角色/多少个场景/开多少核心技术开关 |
| sk1_character_design + sk2_scene_design → sk3_storyboard_split | SK3 拆分镜需要知道角色/场景数量/ID，跨段要追踪角色状态变化，角色场景不齐全没法写分镜时间轴 |
| sk3_storyboard_split → sk4_prompt_generator | SK4 的提示词 3 次夹攻 + 动作时间戳 + 嘴口型窗口严格依赖 SK3 的四维对齐表，SK3 没拆完 SK4 就不知道一段有几秒/动作在第几秒/嘴窗是多少秒 |
| sk4_prompt_generator → sk5_consistency_audit | SK5 校验 6 步检查 + 四档打标是基于 SK4 生成的提示词检查，没生成就没得打 |

> 说明：sk0b_missing_field_guide 是全局 pre-hook（挂在 SK0 之后每一个 Skill 开始前都会调用一次补确认），不是节点之间的串行边。

## 二、完全并行边表（互相完全不依赖，同时跑节省总时间）

| 并行节点 A ↔ 并行节点 B | 为什么完全可以并行？ |
|---|---|
| sk1_character_design ↔ sk2_scene_design | 角色设定和场景设定互相不依赖，两个可以同时问用户，同时写文档，不需要等对方 |
| sk3_storyboard_split ↔ sk6_postproduction_bundle | 字幕/TTS/剪映三件套**只依赖 SK3 的时间轴和台词原文**，不需要等视频生成/提示词写完！分镜一拆完立刻生成字幕/TTS清单/剪映手册，用户在 SK4 写提示词的时候，后期文件已经准备好了，节省大量时间 |
| sk4_prompt_generator ↔ sk6_postproduction_bundle | 同上，SK6 已经在 SK3 跑完就生成好了，和 SK4 写提示词/用户生成视频完全同步并行，不需要等 |

## 四、6 种入口自适应的跳步流程（D1 要求灵活，不强制完整故事）

### 入口 1：完整故事原文 ready（最完整流程）
> 跳步：不跳，完整 sk0→sk0b→sk1&sk2 并行→sk3→sk4→sk5 打标→用户生成→sk6 并行

### 入口 2：大纲 ready，没写完整原文
> 跳步：SK0 → SK0b 补问原文空白的关键信息，其余流程同 1，其他步骤不跳

### 入口 3：角色+场景 ready，没故事
> 跳步：SK0 入口类型选「角色场景已 ready」，SK0b 补问剧情骨架，SK1/SK2 直接拿用户现成的角色/场景做一致性升级（补 3 行完整前缀 / cm 锚点等缺项），直接进 SK3，不跳其他步骤

### 入口 4：单段片段 ready（咖啡馆示例就是这个）
> 跳步：SK0 入口类型选「单段片段现成」，SK1 只要设计片段里出现的 2 个角色不用写全配角，SK2 只要设计这一个场景，SK3 不需要拆分镜直接写这段，SK4~SK6 正常走，最少只需要 10 秒就能跑完整个 Skill 流程

### 入口 5：分镜 ready
> 跳步：SK0 入口类型=「分镜现成」，SK0b 补确认缺项，SK1/SK2/SK3 跳过，直接 SK4→SK5→用户生成→SK6 并行，3 个步骤就出片

### 入口 6：提示词 ready，只要校验 + 后期
> 跳步：最快，SK0 入口=「提示词现成」，SK1~SK4 全部跳过，直接 SK5 打标 + SK6 生成后期，两步搞定

## 五、串并行调度总结（给 Agent 的调度逻辑伪代码）
```
调度算法（遇到视频生成任务按这个跑）：
1. 先强制跑 SK0，拿到 entryType + 12 项配置
2. 按 entryType 决定跳哪些步骤（上面第四节的跳步规则）
3. SK0b 作为全局 preHook：进入每个 SK* 前都调一次 SK0b 补确认缺项，没缺就空过
4. 不跳过的节点按串并行边表：
   - 串行边按顺序跑，不能同时
   - 并行边开两个并发分支同时跑
5. 等 SK3 完立刻开 SK6，不等 SK4/SK5
6. 最终用户生产阶段（画图/生成视频）由用户完成，SK5 每完成一项更新四档打勾
```
